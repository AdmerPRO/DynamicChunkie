# Hot/soft integration measurements — 2026-11-19

Runtime feature commit: `fd8a588`; benchmark harness including AFK guard: `533bad9`.
Minecraft 26.3, DynamicChunkie 0.1.0, Java 25.0.5.1, Linux, 12 logical processors,
NVIDIA GeForce RTX 3060 / Vulkan (device reported in client logs), 854×480 window.
The JSON backend description is the LWJGL library version, not GPU utilization.
RD 8, VSync off, unlimited foreground FPS, AFK limiting disabled, 5 ms scan budget.
Each phase warms for 100 ticks and records 200 ticks, with two repetitions in AB/BA order.

These are small synthetic Fabric client-test workloads with a synchronized test
scheduler. The very high frame rates are not representative of normal gameplay.
Two repetitions do not establish statistical significance or a universal gain.
The offscreen-update vanilla scene had a large late-run timing outlier; its FPS
comparison is marked UNSTABLE. Earlier reports without AFK protection were
excluded. Read [the protocol](../hot-soft-benchmarks.md) before extrapolating.

The full build and 66 unit tests passed. Both complete client integration suites
(vanilla and Sodium 0.9.3-beta.1+mc26.3 with Mod Menu) passed, including hot/soft
membership, diagonal neighbours, cold update admission, urgent/initial build
safety, returning to view and disabling. Both guarded benchmark processes exited
successfully. Simulation Distance assertions passed.

## Interpretation

Vanilla skipped zero additional geometry sections in the top-down scene, one on
the horizon and four under the synthetic roof. Sodium already excluded the same
geometry in these scenes, so its additional draw-skip count was zero. Small FPS
changes without additional skips should not be attributed to eliminated drawing.
The offscreen-update treatment queued one unique cold section in each repetition;
this counter counts unique pending coordinates, not every rejected rebuild request.
No treatment frames fell back to native visibility in these reports.

This implementation retains cold geometry and client chunk data. It does not
explicitly evict either, and these results do not demonstrate RAM/VRAM savings.
The charged metadata is an estimate based on peak reservations, including retained
hash tables after clearing. JVM heap snapshots include the integrated server,
GC and unrelated renderer allocations. GPU VRAM is not measured.

The feature remains experimental and disabled by default. Measure your actual
world and modpack before enabling it for performance reasons.
